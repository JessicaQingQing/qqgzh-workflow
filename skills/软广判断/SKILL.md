# 软广判断 & 读者连接

写文章之前先想清楚两件事：这篇要不要带货？底部怎么让读者加你？——两件事独立，但都在动笔前定好。

## 如果你还没有产品

非常正常。很多人是先写内容积累读者，后面才有产品：

1. **别硬推。** 说："没有产品很正常，先写内容积累读者。等你有了方向再加。"
2. **给方向建议。** 根据用户的 Profile 和聊天内容，提 1-2 个以后可以考虑的商业方向。比如："以后如果你积累了一批职场人读者，你八年项目管理经验可以做成付费模板、一对一咨询、或者企业内训。"
3. **offer 留空。** Profile 里的 `monetization.offers` 保持 `[]`。审查不会因为这个卡你——底部的关注入口照样有。
4. **提醒一下。** "以后有了产品，往 Profile 的 monetization 里加一行就行，不用改别的地方。"

## 第一层：读者连接 CTA（每篇都有，雷打不动）

每篇文章底部 `— END —` 之后的固定入口：

```
对 [你的领域] 感兴趣？关注公众号「[公众号名]」后私信「[暗号]」，一起聊聊。
```

这个是**常驻的**：
- 不随文章话题变化，每篇一样。
- 文案从 Profile 的 `connection.invitation` 里取。
- 「暗号」有三个作用：降低读者主动私信的心理门槛、帮你看哪个话题最吸引人、让读者觉得"我发这个暗号是有目的的"而不是瞎聊。

## 第二层：软广落点（每篇选配，不强制）

**文章话题和产品自然对得上才推。** 对不上就跳过——硬塞比不塞更差。

### 怎么判断对不对得上

读完用户的话题，看一眼 Profile 里的 `monetization.offers`，问自己：

1. 对这篇文章感兴趣的读者，会自然地需要这个产品吗？
2. 推这个产品，读起来像是"文章看完了顺便说一下"，还是"写到一半突然拐弯卖东西"？

对不上就说："这篇不适合带产品，纯内容就挺好的。"

### 三种自然的带货方式

- **工具延伸** — 文章教方法 → 产品是把方法变简单的工具（模板、清单、工作表）
- **实践延伸** — 文章讲框架 → 产品是动手练的场景（训练营、社群、陪跑）
- **服务延伸** — 文章诊断问题 → 产品帮你解决（咨询、代做服务）

### 红线（来自 `references/monetization-patterns.md`）

- 软广占比 ≤ 全文 20%
- 观点先行、身份后置；给洞察、再给 offer
- 同一个落点只出现一次，别反复刷
- 匹配度 > 说服力：说"看适不适合你"而不是"你应该买"
- 不编紧迫感、不编稀缺、不编保证
- 所有说法要能核实——别瞎编效果
