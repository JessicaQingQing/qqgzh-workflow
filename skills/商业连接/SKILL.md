# 商业连接 & 读者入口

这个 Skill 回答两个问题：这篇内容要不要有商业落点？要不要给读者一个继续连接的入口？——两个问题独立，答案都不是"每篇都要"。

## 先判断这篇需不需要商业连接

**以下情况不需要，直接跳过：**
- 这是一份职业资产卡、方向卡、选题清单——过程稿，不是公开发布的内容
- 用户还没有产品或不想推任何东西
- 文章主题与用户的商业方向完全对不上
- 用户明确说"这篇不想带任何东西"

**以下情况可以考虑：**
- 这是正式发布到公众号的成品文章
- 用户有明确的产品或服务（咨询、课程、模板等）
- 文章主题自然导向那个产品——读者看完会觉得"接这个 offer 很合理"
- 用户主动说"这篇可以引导一下"

跳过时直接说一句"这篇纯内容就挺好的，不加商业落点。"然后正常进入排版。

## 第一层：读者连接入口（选配，非强制）

读者连接 CTA 是文章底部 `— END —` 之后的关注/私信引导。格式：

```
对 [你的领域] 感兴趣？关注公众号「[公众号名]」后私信「[暗号]」，一起聊聊。
```

**这个连接入口由 Profile 控制：**
- 只有 `connection.enabled = true` 时才加
- 文案从 Profile 的 `connection.invitation` 读取
- 用户可以在 Profile 里关掉——很多人在第 1/2 层探索阶段不需要这个
- 如果不加，审查不会因为这个拦截

## 第二层：商业落点（选配，不强制）

文章话题和产品自然对得上才推。对不上就跳过——硬塞比不塞更差。

### 怎么判断对不对得上

读用户的话题和 Profile 里的商业配置，问自己：

1. 对这篇文章感兴趣的读者，会自然地需要这个产品吗？
2. 推这个产品，读起来像是"文章看完了顺便说一下"，还是"写到一半突然拐弯卖东西"？

### 三种自然的连接方式

- **工具延伸** — 文章教方法 → 产品是把方法变简单的工具（模板、清单、工作表）
- **实践延伸** — 文章讲框架 → 产品是动手练的场景（训练营、社群、陪跑）
- **服务延伸** — 文章诊断问题 → 产品帮你解决（咨询、代做服务）

### 红线

- 商业落点占比 ≤ 全文 20%
- 观点先行、身份后置；给完洞察再给 offer
- 同一个落点只出现一次，别反复刷
- 匹配度 > 说服力：说"看适不适合你"，不说"你应该买"
- 不编紧迫感、不编稀缺、不编保证
- 所有说法要能核实——不编效果

## 如果用户还没有产品

非常正常。很多人是先积累读者，后面才有产品：

1. 不硬推。说"没有产品很正常，先写内容。等你有了方向再加。"
2. 可以给 1-2 个以后可能的方向建议，但用试探口吻："以后如果你积累了一批读者，你的经验可能自然导向 X 或 Y。现在不用定。"
3. Profile 里的商业配置保持默认（关闭或空）。
4. 以后有了产品，往 Profile 里加就行。

## 与其他模块的关系

- **上游**：这个 Skill 只在用户进入第 4 层（渠道发布）时被调用。第 1-3 层的产出不经过这里。
- **下游**：商业连接方案（或"跳过"的决定）传给排版 Skill，排版 Skill 据此决定 HTML 里是否包含 `.connect` 和 `.cta` 区块。
- **审查**：`发前审查` 的检查项里，`.connect` 和 `.cta` 只在商业连接方案声明了要加时才检查；声明了不加工就不检查这些项。
